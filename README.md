# DVLD Graduation Project

مشروع تخرج لإدارة معاملات ورخص القيادة، مع تطبيق موظفين Windows Forms وواجهات API، وبنك أسئلة يعتمد على وثائق PDF وذكاء اصطناعي محلي.

هذا الملف يشرح ما يظهر في المصدر الحالي. دليل الشرح التفصيلي أُعد بتاريخ **2026-10-06** من فرع **`feature/shared-layers`** عند commit [`ad66e2a`](https://github.com/emadAlaa2003/DVLD_GraduationProject/commit/ad66e2a).

## الوظائف الموجودة في المصدر

- إدارة الأشخاص والموظفين والطلبات والمواعيد والرخص المحلية والدولية.
- رفع وثائق PDF، حفظ بياناتها، ومعالجة نصوصها في الخلفية.
- شات RAG يسترجع مقاطع المعرفة قبل بناء الإجابة.
- توليد Multiple Choice وTrue/False من وثيقة جاهزة مع حفظ المصدر والصفحة والدليل.
- مراجعة الأسئلة كـDraft واعتمادها أو رفضها.
- تسجيل Job للتوليد ومتابعة حالته من تطبيق الموظف.
- API للرخص والطلبات والمواعيد والامتحان الرسمي.

الامتحان الرسمي مخصص للكمبيوتر وفق نطاق الفريق. مشروع الموبايل ليس ضمن الملفات التي شملها هذا الدليل.

## كيف يعمل مسار الـAI؟

1. يحفظ API ملف PDF وبياناته، ثم يضع مهمة المعالجة في طابور الذاكرة.
2. يستخرج PdfPig النص، وتعالجه الأدوات المحلية وتقسمه إلى مقاطع مع معلومات الصفحة والمصدر.
3. يرسل النص إلى Ollama لحساب embeddings، ويخزن المقاطع ومتجهاتها في Qdrant.
4. للشات: يسترجع مقاطع مرتبطة بالسؤال، ثم يستخدم خدمة reranker محلية قبل إرسال السياق إلى نموذج الإجابة.
5. لتوليد الأسئلة: يختار مصادر من الوثيقة، ويطلب مخرجات منظمة، ويتحقق منها ومن الدليل، ثم يحفظ الأسئلة Draft للمراجعة البشرية.

لا يظهر تدريب أوزان أو fine-tuning في هذا المسار. المقاطع تُرسل للنموذج وقت الطلب، ولا يُعتبر وجود الدليل ضمانًا كاملًا لصحة السؤال.

## تجهيز التشغيل

1. على Windows افتح [DVLD/DVLD.sln](DVLD/DVLD.sln)، ووفّر أدوات بناء .NET Framework 4.8 و.NET 10، ثم استرجع حزم NuGet.
2. جهّز SQL Server وقاعدة بيانات مطابقة للمصدر. عيّن متغير البيئة `DVLD_CONNECTION_STRING`، وأعد فتح بيئة التشغيل عند تغييره.
3. جهّز Ollama بالنموذجين `qwen3-embedding:0.6b` و`qwen3:1.7b`.
4. جهّز Qdrant عبر `localhost:6334` وcollection باسم `dvld_knowledge` بحجم متجه 1024 وCosine.
5. شغّل خدمة reranker المحلية على `http://localhost:8081/rerank`. تنفيذ خادم هذه الخدمة غير موجود ضمن الملفات المفحوصة.
6. شغّل API بملف تعريف HTTPS، ثم تطبيق WinForms بحساب موظف فعال وبيانات تجريبية.

```powershell
ollama pull qwen3-embedding:0.6b
ollama pull qwen3:1.7b
dotnet run --project .\DVLD.Api\DVLD.Api.csproj --launch-profile https
```

عناوين التطوير في [launchSettings.json](DVLD.Api/Properties/launchSettings.json): `https://localhost:7077` و`http://localhost:5277`. الوصول من هاتف يحتاج عنوان الخادم المناسب وثقة شهادة HTTPS؛ `localhost` على الهاتف يشير إلى الهاتف نفسه.

## البيانات والملاحظات الحالية

- [Database/Migrations](Database/Migrations/) يحتوي migrations جزئية؛ لا يوجد فيه script شامل لإنشاء كل القاعدة أو جدول `QuestionGenerationJobs`.
- نسخة SQL الاحتياطية لا تشمل ملفات PDF ولا بيانات Qdrant. مجلد الوثائق المرفوعة وملفات `.bak` وبيانات الاتصال المحلية مستثناة من Git.
- لم تُثبت الملفات وجود مصادقة مواطن أو تحقق ملكية السجلات، وصلاحيات الموظفين ليست موثقة كميزة مكتملة.
- الطوابير الحالية داخل الذاكرة؛ لا يظهر استئناف تلقائي للمهمات بعد إعادة تشغيل API.
- واجهة الموظف تتابع Job واحدًا، وعرض أسئلة النتيجة يعتمد على أحدث Draft للوثيقة والعدد، لا ربط كل سؤال بهوية Job.
- توجد ملاحظات لمعالجة فشل التوليد، وبعض أخطاء القراءة، وحماية مصادر الأسئلة عند إعادة المعالجة، وحد الثقة للشات؛ تفاصيلها في الدليل.
